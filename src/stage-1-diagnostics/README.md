# Диагностика и worker демопрототипа Б24

Каталог содержит страницу чтения интерфейса Б24, тест регистрации диагностической вкладки и выключенный worker. Это исходники статичного приложения, но пакет worker не размещён в текущем портале и не зарегистрирован.

## Текущее состояние

- `index.html`, `probe.js`, `bind.js` — диагностика scope и placements; привязка диагностической вкладки ограничивается тестовой группой.
- `navigation.js` — построение пути стандартной формы через `BX24.openPath`; это не доказывает сохранение параметров или работу из 1С.
- `worker.html`, `background_worker.js`, `worker-config.js` — прототип очереди через личные REST-хранилища `Q_<userId>` и `R_<userId>`. Service-origin и передача браузерного токена отсутствуют.
- Worker проверяет iframe и `BXDesktopSystem.ExecuteCommand`, использует постоянный `workplaceId`, отдельный `instanceId`, ожидает адресованное ему разрешение и сообщает состояния открытия/закрытия.
- Конфигурация остаётся выключенной: `enabled=false`, `standardCardVerified=false`.

В текущем доступном списке портала приложение №80 отсутствует. Новое приложение не создавать и другой ID не менять. После идентификации целевого приложения в нём должны быть `task`, `placement`, `user_brief`, `entity`; только затем отдельно проверяются worker и права хранилищ. До этого пакет не загружать и не регистрировать.

## Исторические диагностические результаты

2 октября был выполнен диагностический прогон страницы приложения: после повторной загрузки чтение scope/placements завершилось, список placements содержал точки задач, основной интерфейс не показывал команд или событий. Это не доказывает отсутствие команд в контексте карточки задачи.

В историческом прогоне зарегистрирована вкладка `TASK_VIEW_TAB` только для проекта «Гем платежи демо» (ID 36); повторное чтение подтвердило привязку. Вкладка отсутствовала в новой несохранённой карточке задачи и не была проверена в сохранённой задаче. Задачи не создавались.

Прежние записи об установленном приложении №80 и интеграции №90 относятся к прошлому состоянию портала. В текущем доступном списке ID 80 не найден; scope, пути и обработчики существующих приложений не менялись.

## Локальные проверки

Из корня репозитория:

```powershell
node --test tests/stage1/*.cjs
```

Тесты подтверждают построение URL, отказ обычному браузеру, фильтрацию сообщений `entity`, ID рабочего места/окна, отсутствие открытия без точного разрешения, heartbeat и перевод закрытия в неизвестный исход. SDK и REST в автоматизированных проверках подставляются; портал, desktop bridge, сохранение метки и возврат ID ими не подтверждаются.
