# Диагностика и worker демопрототипа Б24

Каталог содержит страницу чтения интерфейса Б24, тест регистрации диагностической вкладки и выключенный worker. Это исходники статичного приложения, но пакет размещён в приложении №80 и персональный worker зарегистрирован; обработка очереди выключена.

## Текущее состояние

- `index.html`, `probe.js`, `bind.js` — диагностика scope и placements; привязка диагностической вкладки ограничивается тестовой группой.
- `navigation.js` — построение пути стандартной формы через `BX24.openPath`; это не доказывает сохранение параметров или работу из 1С.
- `worker.html`, `background_worker.js`, `worker-config.js` — прототип очереди через личные REST-хранилища `Q_<userId>` и `R_<userId>`. Service-origin и передача браузерного токена отсутствуют.
- Worker проверяет iframe и `BXDesktopSystem.ExecuteCommand`, использует постоянный `workplaceId`, отдельный `instanceId`, ожидает адресованное ему разрешение и сообщает состояния открытия/закрытия.
- Конфигурация остаётся выключенной: `enabled=false`, `standardCardVerified=false`.

5 октября 2026 года подтверждено: запись интеграции №90 ведёт к установленному приложению №80. По ранее полученному подтверждению добавлены `user_brief` и `entity`, сохранены `task` и `placement`. Пакет диагностики и выключенного worker размещён в этом приложении. Регистрация worker с USER_ID и errorHandlerUrl подтверждена чтением; скрытый фрейм в десктопном клиенте показал desktop_detected. Стандартная карточка сохранила точный тег демозадачи №9926 после ручного изменения текста. Права личных хранилищ и полный обмен ещё не проверены.

## Исторические диагностические результаты

2 октября был выполнен диагностический прогон страницы приложения: после повторной загрузки чтение scope/placements завершилось, список placements содержал точки задач, основной интерфейс не показывал команд или событий. Это не доказывает отсутствие команд в контексте карточки задачи.

В историческом прогоне зарегистрирована вкладка `TASK_VIEW_TAB` только для проекта «Гем платежи демо» (ID 36); повторное чтение подтвердило привязку. Вкладка отсутствовала в новой несохранённой карточке задачи и не была проверена в сохранённой задаче. Задачи не создавались.

Прежний вывод об отсутствии приложения №80 был ошибочным: ID записи интеграции и ID установленного приложения различаются. Проверка 5 октября подтвердила связь №90 → №80; другие интеграции не менялись.

## Локальные проверки

Из корня репозитория:

```powershell
node --test tests/stage1/*.cjs
```

Тесты подтверждают построение URL, отказ обычному браузеру, фильтрацию сообщений `entity`, ID рабочего места/окна, отсутствие открытия без точного разрешения, heartbeat и перевод закрытия в неизвестный исход. SDK и REST в автоматизированных проверках подставляются; портал, desktop bridge, сохранение метки и возврат ID ими не подтверждаются.

## Диагностика 5 октября

`correlated_probe.js` открывает стандартную карточку только в нативной среде, передаёт название/проект/точный тег и перечитывает найденные задачи. Описание вводится вручную. Пустой поиск означает неизвестный результат; несколько точных совпадений — конфликт. Поддержаны страницы SDK и фактические объекты TAGS `id/title`.

`worker_probe.js` регистрирует worker текущего пользователя и сверяет сохранённые значения; чужая конфликтующая регистрация не заменяется. `worker.html` сохраняет диагностическое наблюдение среды даже при выключенной очереди. Обычная браузерная страница отказала открытию; отрицательный прогон скрытого браузерного worker пока не завершён.

Актуальные живые результаты и ограничения: [B24-14/B24-15](../../docs/stage-1-prototypes.md#продолжение-5-октября-2026-года).
