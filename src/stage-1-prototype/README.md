# Прототип расширения T05

Штатная XML-выгрузка расширения «Б24ПрототипЭтап1» из «КА Демо», выполненная Конфигуратором 1С 8.3.23.2040 1 октября 2026 года. Конфигурация: КА для Казахстана 2.4.5.18; совместимость расширения: 8.3.21. UUID, имена и формат выгрузки сохранены.

**Это незавершённый технический прототип. В рабочую базу не устанавливать.** Синтаксис и проверка применимости пройдены. После исправления безопасного режима демопрототипа блок подтверждён в живом интерфейсе существующего заказа нового сеанса. Подробности, Red и Green: [протокол этапа 1](../../docs/stage-1-prototypes.md#ka-02--блок-формы-red-и-green-в-демобазе).

## Собственная логика

Модуль `Documents/ЗаказКлиента/Forms/ФормаДокумента/Ext/Form/Module.bsl` после штатного `ПриСозданииНаСервере` добавляет группу «Задача Битрикс24» и пояснение. Группа пока не содержит рабочие команды или ссылку. Её историческое пояснение о нереализованном хранении относится к пользовательскому сценарию: регистр добавлен отдельно, форма его ещё не читает.

После штатного клиентского `ПослеЗаписи` диагностический обработчик проверяет режим проведения и `ПринудительноЗакрытьФорму`. При сохранённом проведённом заказе без связи сервер записывает `STAGE1_POST_CLOSE` в журнал регистрации. В новом сеансе подтверждены успешное проведение с закрытием, отсутствие вызова при обычной записи, проведении без закрытия, отказе по предоплате и существующей синтетической связи. Это проверка точки подключения; Б24 и сервис не вызываются. Ошибка диагностики перехватывается, но отдельный прогон сбоя серверного вызова пока не выполнен.

Собственный независимый непериодический регистр `Расш1_СвязиЗаказовБ24`: измерение `Заказ`, ресурсы `ЗадачаId` и `ОперацияId`. Модуль набора записей блокирует весь регистр в транзакции платформы и проверяет сохранённые связи по всем трём значениям; точный повтор допустим, другая пара для занятого заказа, задачи или операции отклоняется. Повторы задачи и операции внутри одного пакета также отклоняются. Это прототип, без полной проверки входных данных, ручной замены и очистки с аудитом.

Заимствованы документ «ЗаказКлиента», `ФормаДокумента`, `ФормаСписка` и связанные перечисления, картинки и элементы стиля, автоматически выбранные Конфигуратором. Добавлена штатная основная роль расширения. Модуль `ФормаСписка` добавляет отдельное вычисляемое поле и колонку после «Клиент»; штатный запрос и поле ссылки не заменяются. Порция списка читает собственный регистр и получает текст `Задача №{ID}` через оформление поля. Пустая колонка, заполнение синтетическим номером из регистра и очистка после обновления подтверждены в живом клиенте. Реальной задачи с этим номером нет: это проверка отображения, не интеграции. Переход, поиск и сортировка по задаче, обращение к Б24 и сетевой обмен отсутствуют. Подключение к успешному «Провести и закрыть» проверено диагностическим событием. Основная конфигурация не изменена.

## Воспроизведение только в демобазе

1. В Конфигураторе открыть **«Конфигурация → Расширения конфигурации»**.
2. Для существующего прототипа выбрать **«Конфигурация → Загрузить конфигурацию из файлов»** и этот каталог. На другой тестовой базе сначала создать отдельное расширение. Основную конфигурацию не загружать и не заменять.
3. Сохранить расширение, выполнить штатную проверку модуля и применимости расширения, применить изменения только к демобазе. В проверенной демосреде безопасный режим запрещал расширение модуля формы; он отключён только у этого прототипа, защита от опасных действий оставлена включённой. Настройка подключения в базе не заменяется наличием XML-выгрузки.
4. Запустить новый сеанс 1С. Открыть новый заказ без сохранения; проверить наличие группы и сообщения. Закрыть заказ без записи. Сохранённые заказы для проверки группы не изменять.
5. Открыть «Заказы клиентов»: колонка «Задача Б24» расположена после «Клиент», при пустом регистре ячейки пусты. Зафиксировать фактический результат в протоколе. Наличие XML, отсутствие синтаксических ошибок и запуск сеанса не заменяют проверку отображения группы.

Первоначальный Green использовал существующий демозаказ: Ctrl+Shift+F → «Заказ клиента» → Enter, чтение блока в интерфейсе, Ctrl+F4 без записи и проведения. Затем отдельно проверен новый незаписанный заказ: RPC подтвердил отсутствие ссылки документа и наличие блока, открытая форма показала блок в живом дереве и на снимке. Заказ закрыт без записи и проведения.

Автоматизированного запуска этой проверки в репозитории нет. При работающем MCP диагностический фрагмент KA-02 выполняется через `execute_code` в контексте `client`; результат старого сеанса, который не загрузил расширение, не является проверкой новой версии.

## Проверка регистра

[Сценарий](../../tests/stage1/register_contract.bsl) выполняется через Toolkit `execute_code` в контексте `server` только в демобазе с загруженным расширением. Он создаёт две синтетические ссылки без записи документов, проверяет повтор, конфликт задачи и операции, сохранность первой связи; затем очищает только собственные тестовые строки. Б24 не вызывается. Разрешение Toolkit подтверждает пользователь; автоматическое разрешение записи не требуется.

До исправления получен фактический `STAGE1_RED: операция принята для другого заказа и задачи`. После исправления загрузка, проверка модулей, применимость и применение прошли. Тот же сценарий в новом сеансе вернул `STAGE1_REGISTER_CONTRACT_GREEN`: точный повтор, конфликт задачи, конфликт операции и сохранность первой связи проверены. После очистки регистр пуст. Конкурирующие сеансы не проверены. Полная `/CheckConfig -HandlersExistence` вернула 39 сообщений о штатных обработчиках заимствованных форм; они не заменены заглушками. Это открытое ограничение проверки.

Штатный экспорт `.cfe` выполнен в исключённую из Git локальную папку. Это промежуточный прототип, не поставка для рабочей базы. Историческая внешняя обработка и Toolkit не изменены; они не являются компонентами этого прототипа. Полная поставка и работа без MCP проверяются на последующих этапах.

В KA-06 отдельно воспроизведён повтор операции внутри пакета из двух строк. После добавления проверки внутри набора [тест](../../tests/stage1/register_batch_operation.bsl) в новом сеансе вернул `STAGE1_BATCH_OPERATION_GREEN`; основной контракт регистра тоже прошёл. Тестовый пакет откатан, собственные строки основного теста очищены; отдельное чтение подтвердило пустой регистр. Это не проверка конкурирующих сеансов.

**Дополнение 2 октября:** KA-08/KA-09 подтвердили конкурирующие конфликты общей задачи, общего заказа и общей операции в двух разных сеансах одной «КА Демо». Во всех трёх случаях наблюдалось перекрытие попыток, вторая запись отклонена, первая связь сохранена, тестовые строки очищены. Отдельное итоговое чтение обоих сеансов подтвердило пустой регистр. [Сценарии и критерии](../../tests/stage1/README.md#конкурирующие-сеансы-1с). Логика расширения не менялась; полная проверка обработчиков и реальный обмен Б24 остаются открытыми.
