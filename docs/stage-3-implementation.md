## Последовательность

1. Зафиксировать решения в PRD и TASKS. Проверить штатные точки проведения/закрытия. По уточнению заказчика 9 октября любые переходы из 1С исключены: отображать ID задачи, без кнопки открытия и гиперссылки.
2. T52: отключить старую очередь от записи. Перехватить `ПровестиИЗакрыть` через `&Вместо`; после «Да»/«Нет» продолжить штатный обработчик однократно, без повторного вопроса. Крестик/Esc отменяют команду. Обычные команды не создают задачу.
3. T51: перед проведением проверить связь, операцию и отмену/пометку заказа; подтверждение после удаления связи получить до проведения. Вызвать штатное проведение без закрытия. Только после подтверждённого успеха сохранить устойчивую операцию и запустить фон. Снимок и повторная проверка состояния — в транзакции резерва под блокировкой; HTTPS — после фиксации. Сбой интеграции не отменяет проведение. Подтверждённая неотправка требует нового клика; неизвестность требует восстановления прежней операции.
4. T53: заменить нижнюю диагностику верхним компактным блоком. Только сохранённая связь устанавливает признак создания. Состояния создания/неизвестности/известного ID без связи отдельные. Название — одна строка с полной подсказкой; ID и состояние полностью. Обновлять только реквизиты интеграции, не терять изменения заказа.
5. T55: команды в «Ещё». Новый незаписанный заказ сначала записывается обычной командой. Показывать проверенного кандидата (ID, полное название, номер заказа), сохранять только по явному подтверждению. Завершённую задачу разрешать после предупреждения. Повторно проверять кандидата, права, версию, уникальность и незавершённые операции. При изменении кандидата требовать новый предпросмотр. Изменение/удаление связи подтверждаются и аудируются; задачу Б24 не менять.
6. T54: колонка после «Клиент», обычный текст «Задача №{ID}» из сохранённой связи; без связи пусто. Удалить команды открытия, обработчик перехода и настройки десктопного запуска. Проверить отсутствие гиперссылки и отображение того же ID в форме и списке.

## Согласованные пограничные случаи

- При существующей связи команда создания не сохраняет и не проводит заказ. Сообщить о существующей задаче; при изменённой форме явно указать, что изменения не сохранены и задача не обновлена.
- Закрытие напоминания крестиком/Esc оставляет заказ открытым и не запускает проведение.
- Отменённый или помеченный заказ не допускает нового создания. Связь и отображение ID сохраняются. Критерий отмены общий с этапом 2: все товарные строки отменены либо закрытый заказ имеет отменённые строки; обычное закрытие выполненного заказа и снятие проведения не являются отменой.
- Если устойчивую операцию создать не удалось, успешное проведение сохраняется. При подтверждённом отсутствии отправки: «Заказ проведён. Создание задачи не запущено. Повторите команду позже». При неопределённости сначала проверить журнал.
- Завершённую задачу можно привязать после предупреждения; статус не меняется.
- Длинное название сокращается только в отображении, хранится полностью.
- Привязка требует предпросмотра и кнопки «Привязать»; незаписанный заказ автоматически не сохраняется.

## Контракты

Сохранить серверную основу состояния, операций и восстановления. Добавить безопасную предварительную проверку кандидата; подтверждение передаёт ожидаемую версию и проверенные ID/название/завершение. Секрет и исходные REST-ответы клиенту не передаются. Команд запуска внешних приложений нет. Новых постоянных регистров и внешних служб нет.
