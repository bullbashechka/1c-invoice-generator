# Этап 0: фактическая готовность среды

Дата проверки: 30 сентября 2026 года, UTC+5. Основание: `PRD.md` §§2, 5, 8–10 и T01–T04 в `TASKS.md`.

**Статус: выполнена доступная часть подготовки; этап 0 не закрыт.** Ниже разделены фактические наблюдения, решения пользователя и невыполненные проверки. Запуск приложений, чтение метаданных и создание тестового проекта не подтверждают три механизма интеграции этапа 1.

## Решения пользователя

- Разработка и проверка 1С выполняются в тестовой базе. Проверенное расширение устанавливается в рабочую базу после приёмки.
- Тестовые задачи и уведомления на рабочем портале Б24 допустимы; зацикливание недопустимо.
- По уточнению во время выполнения создан отдельный проект **«Гем платежи демо»**. Он используется для тестирования вместо рабочего проекта «ГЕМ Платежи».
- По последующему уточнению в демопроект никого не добавлять. Сейчас в нём только создавшая проект учётная запись. Отправка приглашений не выполнялась.
- Производственное назначение участников и проекта из PRD не изменяется. Проверка под реальными сотрудниками и с производственным проектом остаётся отдельной невыполненной проверкой.
- Название задачи берётся строго из «Контрагента» с добавлением точки. «Клиент» используется отдельно в описании.
- Если результат предыдущей попытки создания неизвестен, перед повторным открытием новой формы необходимо проверить предыдущую операцию. Это требование к последующим этапам, а не реализованный механизм.

## T02. Тестовая среда и изоляция

Фактически доступна файловая демобаза. Она уже явно обозначена как демонстрационная в интерфейсе. Её персональное подключение сохранено локально; отдельность от рабочей базы пока не подтверждена сравнением двух подключений. Рабочие документы не изменялись, новая копия базы не создавалась и открытый файл базы не копировался.

Чтением регламентных заданий установлено: 138 экземпляров заданий, 15 имеют `Использование = Истина`. Среди включённых есть `ВыгрузкаДанныхВСервисПрогнозированияПродаж` и `ЗагрузкаДанныхИзСервисаПрогнозированияПродаж`. Это не свидетельство фактической отправки или выполнения задания. Подключения обменов, блокировка внешних ресурсов и действующее расписание исполнения ещё не проверены; изоляция внешних отправок не подтверждена. Задания не отключались на основании одного названия.

На рабочем портале создан закрытый проект «Гем платежи демо», доступный создателю. В нём подтверждено открытие списка задач. Проверенные ID проекта и наблюдения находятся в `.local/stage-0/`; в отчёт ID и персональные ссылки не включаются. Тестовые задачи и новые заказы на этом этапе не создавались. Для проверки реквизитов прочитан один уже сохранённый демозаказ; он не изменялся.

Два независимых пользовательских сеанса не подготовлены. Повторный сеанс того же пользователя не засчитывается как проверка двух сотрудников. Демопроект остаётся с одним участником по указанию пользователя.

### Остановка будущего прототипа

До первого подключения обработчиков этапа 1 требуется реализовать и проверить следующий порядок:

1. Допуск новых операций выключен по умолчанию; включение выполняется только в подтверждённой тестовой среде и для демопроекта.
2. Отдельный выключатель прекращает запуск новых операций. Отключение источника событий и планировщика прекращает новые доставки и попытки; сведения незавершённых операций сохраняются.
3. После выключения повторное событие и обновление связи не открывают новые формы и не создают задачи. Повторные попытки имеют паузу и конечный предел, выбранные и проверенные в прототипе восстановления.

Это порядок проверки для этапа 1. Выключатель, подписки и повторные попытки пока не реализованы. Непрерывная обработка событий интеграции не запускалась. Работа существующего MCP не является обработкой событий целевой интеграции.

**T02 остаётся открытой:** не подтверждены актуальная тестовая копия, изоляция внешних обменов и два пользовательских сеанса.

## T04. Соответствия данных

Соответствия подтверждены живыми метаданными **КА 2.4.5.18 в демобазе**. Для другой версии требуется повторная проверка.

| Данные | Источник | Тип / правило |
| --- | --- | --- |
| Документ | `Документ.ЗаказКлиента` | «Заказ клиента» |
| Контрагент для названия | `Контрагент` | `СправочникСсылка.Контрагенты`; представление для названия ещё проверить на форме |
| Клиент для описания | `Партнер` | `СправочникСсылка.Партнеры`, синоним «Клиент» |
| Сумма | `СуммаДокумента` | Число(15, 2); не сумма табличных строк, придуманная интеграцией |
| Валюта | `Валюта` | `СправочникСсылка.Валюты`; формат отображения ещё проверить на форме |
| Номер | Стандартный реквизит `Номер` | Строка(11), фиксированная |
| Дата | Стандартный реквизит `Дата` | Дата и время документа; не текущая дата создания задачи |
| Ссылка | Стандартный реквизит `Ссылка` | `ДокументСсылка.ЗаказКлиента` |
| Навигация | `ПолучитьНавигационнуюСсылку(Ссылка)` | Фактическая ссылка получена для сохранённого демозаказа и записана только локально |

Для одного сохранённого демозаказа подтверждены заполненность номера, даты, контрагента, клиента и валюты; тип суммы — число. Значения и навигационная ссылка не включены в отчёт. Переход в нужную базу из Б24 не выполнялся и остаётся T08.

ID тестового и рабочего проектов получены из наблюдаемых ссылок в интерфейсе и сохранены локально. Кандидаты учётных записей сохранены локально; постоянные ID пользователей пока не подтверждены. Случайные ID элементов выбора сотрудников и `user/30` исторического прототипа не используются как ID обязательных участников.

**T04 остаётся открытой:** нужны постоянные ID четырёх участников и проверка представлений контрагента/валюты в тестовой форме.

## Доказательства и выполненные проверки

Локальные материалы: `.local/stage-0/metadata-summary.json`, `extensions.json`, `order-metadata.json`, `runtime-private.json`, `order-sample-private.json`, `scheduled-jobs-private.json`, наблюдения десктопного Б24, таблица настроек и реестр тестовых объектов. Формат `data` у ответов Toolkit — TOON; файлы являются JSON-обёртками ответа, а не фиктивными структурированными выгрузками.

Выполнены:

- `git status --short` до изменений; исходные `AGENTS.md` и `TASKS.md` были неотслеживаемыми.
- Инвентаризация ОС через `Get-CimInstance Win32_OperatingSystem`, версий процессов через `Get-Process`, разрядности клиента по PE-заголовку.
- Проверка loopback-порта 6003, MCP `initialize` и `tools/list` существующего встроенного сервера.
- MCP `get_metadata` для конфигурации, расширений и `Документ.ЗаказКлиента`.
- MCP `execute_code` только для чтения соединения и прав, получения навигационной ссылки, чтения списка регламентных заданий; перед использованием метода заданий прочитана локальная справка платформы.
- Просмотр нужного портала, проектов, раздела разработчика и выбора сотрудников в десктопном Б24; создание и повторное чтение демопроекта, открытие его списка задач.

Проверка документов: `git diff --check` прошёл; поскольку оба изменённых документа неотслеживаемые, дополнительно проверены строгий UTF-8, отсутствие хвостовых пробелов и маркеров конфликтов, прочитаны записанные файлы. `git check-ignore` подтвердил исключение локальных настроек, подключения и реестра объектов; локальные JSON разобраны без ошибок. SHA256 `AGENTS.md` и `PRD.md` совпали со значениями до правок.

Тесты поведения интеграции и цикл Red → Green не выполнялись: интеграция на этапе 0 не разрабатывалась. Нет подтверждения создания заполненной формы из 1С, автоматического возврата связи и обратного открытия заказа.
