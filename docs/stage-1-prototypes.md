## Согласованный объём

- Только направление из заказа КА в задачу Б24 и возврат связи. T08 и T30–T33 исключены, не выполнены; номера сохранены.
- Автоматическое открытие только после успешного «Провести и закрыть» при пустой связи. Запись и проведение без закрытия форму Б24 не открывают.
- При ручном открытии из несохранённого заказа — штатная запись без проведения. Ошибка записи останавливает переход.
- По умолчанию: название `{Контрагент}.`, Оксана постановщиком независимо от инициатора, Люда исполнителем, Инга наблюдателем, Женя соисполнителем, согласованный проект. ID берутся из проверенных настроек этапа 0.
- Все поля доступны для ручных изменений в пределах штатных прав. Интеграция изменения не отменяет.
- Срок при открытии: текущий день, 23:59 UTC+5. Пересчёт после полуночи исключён. Описание — данные сохранённого заказа на момент открытия, без дальнейшей синхронизации.
- Сотрудник сам создаёт задачу. Закрытие без сохранения оставляет задачу и связь отсутствующими; проведённый заказ сохраняется. Следующее успешное «Провести и закрыть» без связи повторяет открытие.
- Неизвестный результат сначала восстанавливается по прежней операции; повторное создание временно недоступно.
- Связь один к одному, атомарная уникальность, безопасная повторная доставка, ручная привязка, замена и очистка с аудитом остаются обязательными. Сложный интерфейс одновременного создания исключён.
- Браузер и автоматическое сохранение задачи исключены. Собственная форма Б24 не реализуется без отдельного согласования сценария.

## Выполненные прогоны

### B24-01 — наличие стандартной формы в десктопном приложении

Исходные условия: Б24 запущен и авторизован в нужном портале. Действия: раздел задач → «Создать» → полная форма. Ожидание: стандартная несохранённая форма внутри десктопного клиента. Факт: форма открылась, доступны название, описание, постановщик, исполнитель, срок, проект и участники. Значения по умолчанию штатного интерфейса отличаются от PRD: текущий пользователь и другой срок.

**Результат: предварительное наблюдение.** Открытие было ручным внутри Б24. Передача данных из 1С не проверена; T06 не закрыта.

### B24-02 — изменение постановщика без сохранения

Исходные условия: форма B24-01, текущий пользователь отличается от Оксаны. Действия: открыть выбор постановщика, выбрать проверенную на этапе 0 карточку Оксаны. Ожидание: форма допускает другое значение. Факт: Оксана отобразилась постановщиком в несохранённой форме.

**Результат: выбор доступен в этой учётной записи.** Назначение при фактическом сохранении и права другого сотрудника не подтверждены. Это не проверка всех участников и не программное предзаполнение.

### B24-03 — отказ от несохранённой формы

Исходные условия: B24-02, задача не сохранена. Действия: крестик формы → штатное подтверждение «Закрыть без сохранения?» → «Закрыть». Ожидание: отказаться от создания. Факт: форма закрылась, открыт список задач; кнопка «Создать» не нажималась.

**Ограничение UX:** после изменения постановщика стандартная форма требует дополнительного подтверждения закрытия. Один крестик не завершает отказ сразу. Требование не переписано под это поведение; собственная форма для обхода не внедрена. Отсутствие связи и сохранение проведения в связанном заказе здесь не проверялись: форма не открывалась из заказа.

### B24-04 — внешний запуск и публичные интерфейсы

Действия: прочитать регистрацию URL-протокола и официальную документацию. Факт: `bx:` зарегистрирован на установленное приложение с аргументом `--protocolhandler`. Это подтверждает обработчик протокола, но не маршрут заполненной формы задачи.

Официальный [BX24.openPath](https://apidocs.bitrix24.ru/sdk/bx24-js-sdk/additional-functions/bx24-open-path.html) описывает навигацию в слайдере из встроенного приложения. Он не подтверждает запуск из внешнего процесса 1С. [Ссылка botContext](https://apidocs.bitrix24.com/api-reference/chat-bots/chat-bots-v2/imbot.v2/bot-context.html) относится к чату бота и не засчитывается как способ открыть форму задачи.

Дополнительно прочитан публичный модуль `im/v2/lib/desktop-api/dist/desktop-api.bundle.js` настроенного портала. В `openPage` при части настроек есть ветка открытия ссылки браузером; её нельзя переносить в продукт. Исходник сохранён локально. Способ внешнего входа в форму с предзаполнением и идентификатором операции **не подтверждён**; отсутствие найденного маршрута не является доказательством его принципиальной невозможности.

**Прекращённая проверка шаблонов:** в десктопном Б24 просмотрено меню «Задачу по шаблону» и прочитана документация API. Пользователь исключил этот вариант и остановил управление ПК. Шаблон и задача не создавались; вызовы API изменения не выполнялись. При навигации была случайно открыта пустая форма лида; она закрыта без заполнения и сохранения. Это ошибка управления интерфейсом, не часть интеграции. После указания пользователя ввод в приложения прекращён; затем пользователь возобновил работу, и проверки 1С продолжены в KA-05. Требование стандартной формы из 1С остаётся открытым; шаблоны не используются как его замена.

### B24-05 — ограничение участников в коде стандартного компонента

Прочитан уже сохранённый публичный JavaScript штатного `tasks.task`, файл `logic.js` из каталога оформления `templates/.default`. Это исходник стандартной формы, а не пользовательский шаблон задачи; задачи по шаблонам не создавались и не рассматриваются.

В `restrictMemberSelectors()` ограничение пропускается при `IS_SUPER_USER=true`. Иначе изменение постановщика вызывает `restrictResponsible()`: при постановщике, отличном от текущего пользователя, исполнителем подставляется текущий пользователь и контрол исполнителя получает `readOnly(true)`. Ветка нескольких исполнителей отдельно подставляет текущего пользователя постановщиком. Это условные ветки клиентского кода, а не выполненный тест прав другого сотрудника. Срабатывание при начальном серверном заполнении без изменения постановщика не установлено.

После успешного создания компонент вызывает `BX.Tasks.Util.fireGlobalTaskEvent` с данными задачи. Реализация доставки этого события внешней интеграции, идентификатор попытки и восстановление после потери ответа не подтверждены. Наличие вызова не закрывает T06/T07.

Следующий допустимый ручной прогон: войти в десктопный Б24 обычным сотрудником без специальных прав задач, открыть несохранённую стандартную форму, выбрать Оксану постановщиком и проверить возможность выбора Люды исполнителем, затем закрыть без сохранения. Сначала проверять только форму; сотрудников в демопроект не добавлять. Нужен вход пользователя в эту учётную запись; автоматизация аутентификации исключена. F03 и полное программное предзаполнение остаются открытыми.

### KA-03 — регистр и штатные пакетные команды

В Конфигураторе заимствована `ФормаСписка`, создан собственный независимый непериодический регистр `Расш1_СвязиЗаказовБ24`. Измерение — ссылка `Заказ`, ресурсы — `ЗадачаId` и `ОперацияId`. Модуль набора записей берёт исключительную управляемую блокировку всего регистра внутри транзакции платформы и отклоняет несовпадающую уже сохранённую связь заказа или задачи. Это минимальный прототип, не реализация ручной замены/очистки и аудита.

**Red:** до создания регистра работающий сеанс не находил его в метаданных; колонка `Расш1_ЗадачаБ24` также отсутствовала. Ошибка чтения серверного `ТекстЗапроса` на клиенте не засчитывалась как проверка колонки.

На установленной платформе 8.3.23.2040 проверены штатные пакетные операции `DESIGNER /LoadConfigFromFiles ... -Extension Б24ПрототипЭтап1`, `/CheckModules`, `/CheckCanApplyConfigurationExtensions`, `/UpdateDBCfg` и `/DumpConfigToFiles`. ## Черновой контракт обмена — компонент хранения проверен, архитектура не согласована

Кандидат: постоянно доступный сервис хранит операции и результат Б24; расширение получает результат, атомарно сохраняет связь и подтверждает запись. При закрытых клиентах результат ждёт в сервисе до следующего запуска. Сетевая папка с файловой базой не выполняет эту обработку сама.

| Поле | Назначение |
| --- | --- |
| `baseId` | Постоянный идентификатор базы из настроек, без персонального пути подключения |
| `orderId` | Устойчивый идентификатор сохранённого заказа |
| `operationId` | Идентификатор одной попытки; сохраняется при потере ответа и повторной доставке |
| `state` | Состояние попытки, включая неизвестный результат, отмену, готовый результат и конфликт |
| `taskId` | ID фактически созданной задачи в настроенном портале |
| `linkAcknowledged` | Подтверждение успешного атомарного сохранения связи в расширении |

Названия, суммы и свободно редактируемое описание не используются как ключ сопоставления. Источник достоверного `taskId`, передача `operationId` стандартной форме и подтверждённая отмена ещё не выбраны. Локальный HTTP-прототип использует отдельные ключи базы и адаптера; защита сетевого размещения ещё не выбрана. Истечение времени ожидания не означает отмену и не разрешает новую попытку. Противоречивый результат фиксируется как конфликт; существующая связь и задачи сохраняются. Подтверждение сервису отправляется после фиксации связи; повторное подтверждение безопасно.
