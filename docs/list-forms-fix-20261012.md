# Исправление колонки Б24 в списках заказов

Дата: 12 октября 2026 года. Объём: отображение существующей связи, без изменения REST-сценария и основной конфигурации.

## Причина

Расширение дополняло только `Документ.ЗаказКлиента.Форма.ФормаСписка`. Штатный путь пользователя открывал другую форму — `ФормаСпискаДокументов`. Предыдущий контракт списка явно открывал первую форму и не покрывал вторую. До исправления живой тест получил `LIST_FORMS_RED: ФормаСпискаДокументов: отсутствует колонка Б24`.

## Реализованный план

1. Проверить демобазу по сохранённому отпечатку подключения, сохранить исходный CFE и выгрузить обе штатные формы средствами Конфигуратора.
2. Заимствовать вторую форму. Дополнить события создания формы и получения данных таблицы через `callType="After"` в обеих формах. Исключить замену обработчика через `УстановитьДействие`.
3. Вынести подготовку колонки и пакетное чтение связей в общий серверный модуль `Расш1_СпискиЗаказовБ24Сервер`. Модуль непривилегированный, без клиентского серверного вызова и кеширования.
4. Размещать единственную колонку после `СписокПартнер`. Показывать сохранённый ID обычным текстом, без гиперссылки; заказ без связи оставлять с пустой ячейкой. Запрос списка не менять, данные базы не записывать, REST не вызывать.
5. Загрузить исходники, проверить модули и применимость, применить в «КА Демо», выгрузить отдельный CFE, загрузить его обратно и повторно применить. Проверить обратную выгрузку BSL и метаданных.
6. После перезапуска демосеанса повторить контракт обеих форм, проверить существующие связанные и несвязанные заказы при обновлении и повторном открытии, проверить обычный путь меню.

## Сборка и проверки

Среда: платформа 8.3.23.2040, КА для Казахстана 2.4.5.18; совместимость расширения 8.3.21. Работа выполнена только в существующей «КА Демо», MCP 6004.

Все семь штатных операций Конфигуратора завершились с кодом 0. `/CheckConfig -ThinClient -Server -ExternalConnection -ExtendedModulesCheck` сообщил «Ошибок не обнаружено»; проверка применимости успешна. В исходниках второй формы сохранена её обратная штатная выгрузка.

Старая полная выгрузка второй заимствованной формы отвергалась загрузчиком с общей ошибкой XDTO даже без новых обработчиков. Точный ошибочный узел загрузчик не сообщил. Использовано минимальное заимствование формы и таблицы; его успешную загрузку, применимость и живое поведение проверили отдельно. Это дополнительная проблема шаблона выгрузки, а не причина исходного отсутствия колонки.

Живые результаты:

- `LIST_FORMS_COLUMN_GREEN`: обе формы создают одну видимую колонку после «Клиент», только для чтения, без гиперссылки.
- `LIST_FORMS_ROWS_GREEN`: сохранённый ID и пустая ячейка без связи проверены в обеих формах; по два открытия и по два чтения с обновлением. Использованы существующие демозаказы; тест не создаёт задачи или связи.
- Пользователь открыл «Продажи → Заказы клиентов» и подтвердил наличие колонки. Снимок MCP показывает колонку после «Клиент», существующие ID 10052 и 10058, штатные фильтры состояния, срока, приоритета и менеджера.
- Восемь Python-проверок прошли; `git diff --check` без ошибок.

Локальные журналы и подтверждения находятся в `.local/list-forms-fix/`, включая `red.json`, `green.json`, `rows-green.json` и `menu-proof.png`. Они исключены из Git. Разведчик независимо прочитал изменённые исходники: дефектов продукта не выявил. Замечание о выборе помеченного на удаление заказа в runner исправлено исключением таких заказов и стабильной сортировкой.
