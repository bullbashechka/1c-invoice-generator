# ТЗ: связь заказа клиента в 1С:КА с задачей Битрикс24

Статус: функциональные требования согласованы с заказчиком; технические вопросы перечислены в разделе 10.
Дата редакции: 1 октября 2026 года. Уточнения пользователя из обсуждения этапа 1 имеют приоритет над редакцией от 30 сентября.

## 1. Цель и границы продукта

Напоминать сотруднику о создании задачи при проведении заказа клиента, сохранять связь между заказом и задачей и автоматически возвращать ссылку созданной задачи в исходный заказ. Создание заказов из Б24 исключено из объёма.

Документ первой версии — **«Заказ клиента»**, путь: **Продажи → Заказы клиентов → Создать**. Хотя исходная задача директора №9866 использует название «Счёт на оплату», заказчик подтвердил работу с заказом клиента. Это уточнение имеет приоритет над терминологией исходной переписки.

Единственный поддерживаемый интерфейс Б24 — десктопное приложение на компьютере сотрудника. Создание задачи и открытие связанной задачи выполняются только в нём. Веб-версия Б24 полностью исключена из пользовательских сценариев интеграции, в том числе как запасной способ при ошибках. Автоматический переход в браузер и команда открытия задачи в веб-версии не допускаются.

Создание задачи добровольное: автоматически открывается форма, но задача сохраняется только после нажатия сотрудником «Создать» в Б24. Закрытие формы без сохранения не создаёт задачу. Выставление счетов остаётся в КА.

## 2. Среда и подтверждённый прототип

- Тестовая среда: 1С:Предприятие 8.3.23.2040, «Комплексная автоматизация для Казахстана», редакция 2, версия 2.4.5.18.
- Рабочая база — файловая, файл `1Cv8.1CD` находится в сетевой папке на сервере. Сотрудники подключаются отдельным приложением 1С со своих компьютеров.
- Портал: `https://toofirmagem.bitrix24.kz`.
- Исторический прототип `Открытие_b24.epf` открывал форму новой задачи в браузере; заказчик подтвердил его работу. Этот способ открытия исключён из целевой реализации и сохраняется в описании только как основание выполненного исследования.
- Исходники прототипа: `src/Открытие_b24/`; копия модуля формы: `Открытие_b24_модуль_формы.bsl`.

Прототип требует открытой формы обработки в текущем сеансе. Целевая реализация стороны 1С — расширение конфигурации, работающее без запуска внешней обработки и MCP Toolkit и без изменения основной конфигурации. Автоматический возврат ссылки на задачу прототипом не подтверждён. Обратное создание заказа из Б24 исключено.

## 3. Основной сценарий: из КА в Б24

1. Сотрудник создаёт или открывает заказ, заполняет его и нажимает «Провести и закрыть».
2. Выполняются штатные проверки и проведение документа.
3. Только после успешного проведения, если связанная задача отсутствует, на компьютере этого сотрудника автоматически открывается десктопное приложение Б24 с формой новой задачи.
4. Дополнительное подтверждение открытия не требуется. Форма содержит данные из раздела 5.
5. Сотрудник проверяет данные, затем создаёт задачу либо закрывает форму. Постановщик, исполнитель, проект, наблюдатель, соисполнитель и крайний срок предзаполняются по правилам раздела 5; сотрудник может изменить поля перед созданием.
6. После создания задачи её номер и ссылка автоматически сохраняются в исходном заказе, даже если его форма уже закрыта.

При ошибке проведения форма задачи в десктопном Б24 не открывается и задача не создаётся. Обычные «Записать» и «Провести» без закрытия не запускают автоматическое открытие.

Если форма закрыта без создания задачи и связь пуста, следующее успешное «Провести и закрыть» снова открывает форму. Если связь уже есть, повторное проведение новую форму не открывает.

## 4. Элементы формы заказа и связь с задачей

В форме заказа разместить доступный пользователю блок «Задача Битрикс24»:

- номер связанной задачи;
- поле «Ссылка на задачу Б24» с полным кликабельным адресом; переход из 1С открывает задачу в десктопном Б24;
- команду «Создать задачу в Б24» для ручного открытия формы создания;
- возможность указать ссылку на ранее созданную задачу.

В списке «Заказы клиентов» добавить видимую по умолчанию колонку «Задача Б24» сразу после колонки «Клиент». В ячейке показывать кликабельный текст `Задача №{ID}`, открывающий связанную задачу в десктопном Б24. Поле в форме заказа и колонка списка используют одну сохранённую связь.

Хранение и ручной ввод адреса задачи не означают открытие этого адреса в браузере: обработчик перехода из формы и списка должен открывать нужную задачу только в десктопном приложении Б24.

Если задача не создана и существующая задача не привязана вручную, поле и ячейка остаются пустыми. Само открытие формы создания задачи не заполняет ссылку. После создания задачи ссылка появляется после успешного сохранения связи в 1С; при обновлении формы заказа и списка отображается актуальная связь. При ошибке возврата ссылки действуют правила восстановления раздела 7: пустое поле само по себе не доказывает, что задача не была создана.

В первой версии связь строго один к одному: один заказ связан с одной задачей, одна задача связана с одним заказом. Привязывание задачи, уже связанной с другим заказом, запрещено; проверка выполняется и при ручном вводе ссылки, и при автоматическом сохранении связи. При вводе ссылки проверять принадлежность настроенному порталу и корректность идентификатора. Проверку доступности задачи учитывать отдельно: отсутствие прав или недоступность Б24 не должны ошибочно трактоваться как отсутствие задачи.

При наличии связи основное действие блока — открыть связанную задачу. Ручное создание не должно молча заменять существующую связь. Для исправления предусмотрены отдельные команды «Изменить связь» и «Удалить связь» с подтверждением. Они доступны сотрудникам с правом изменения заказа. При изменении или удалении фиксировать пользователя, время, прежнюю и новую связь; при удалении новая связь пуста. Изменение связи также подчиняется правилу один к одному.

Для несохранённого заказа перед ручным созданием необходимо получить устойчивую ссылку на документ: сохранить заказ штатным способом без проведения, с проверкой обязательных полей. Если сохранение не удалось, переход в Б24 не выполнять. Эта деталь подлежит проверке при реализации.

## 5. Заполнение формы задачи

| Поле | Правило |
| --- | --- |
| Название | `{Контрагент}.` — наименование контрагента и точка; без дополнительного текста, номера и даты заказа |
| Описание | Номер и дата заказа, клиент, сумма с валютой и ссылка на документ 1С |
| Постановщик | Оксана |
| Исполнитель (ответственный) | Люда |
| Проект | «Гем платежи» |
| Наблюдатель | Инга |
| Соисполнитель | Женя |
| Крайний срок | День открытия формы задачи, 23:59 по времени Казахстана (UTC+5); сотрудник может изменить |

Данные берутся из успешно сохранённого заказа. Для названия использовать реквизит «Контрагент», не подменяя его реквизитом «Клиент». Соответствия реквизитов проверены в демобазе на этапе 0; для иной конфигурации проверить повторно. Номер и дата заказа остаются в описании; дата заказа не заменяется текущей датой.

Указанные участники и проект — значения предзаполнения независимо от инициатора. Все поля формы доступны для ручного изменения в пределах штатных прав Б24; интеграция сохраняет выбор сотрудника и не возвращает исходные значения. Описание фиксирует данные заказа на момент открытия формы и не синхронизируется с последующими изменениями заказа. Сохранение задачи добровольное. Срок подставляется при открытии формы; пересчёт после полуночи исключён из обязательного поведения и приёмки.

Конкретные учётные записи Оксаны, Люды, Инги и Жени и проект «Гем платежи» выбрать при настройке и сохранить их идентификаторы Б24. Не определять пользователей только по совпадению имени. Значение `user/30` из URL прототипа не считать идентификатором согласованного постановщика или исполнителя без проверки.

Сотрудник работает в своей учётной записи Б24 со штатными правами портала; постановщик по умолчанию — Оксана. Возможность такого предзаполнения и сохранения задачи без ручной замены Оксаны при работе другого сотрудника проверить прототипом. Если прав или технической возможности недостаточно, не подменять постановщика текущим сотрудником; ограничение разрешить до основной разработки по правилам раздела 10.

Правила заполнения применяются ко всем новым задачам, создаваемым из 1С: при автоматическом открытии после проведения и по ручной команде. При ручной привязке существующей задачи её название, участники, проект и срок не изменяются.

## 6. Обратное создание заказа — исключено

По решению пользователя от 1 октября 2026 года действие «Создать в КА» и открытие нового заказа из задачи Б24 не входят в продукт. Раздел сохранён для стабильности нумерации. Возврат ID и ссылки задачи в уже существующий заказ остаётся обязательным механизмом.

## 7. Ошибки, повторные действия и совместная работа

- Недоступность Б24, ошибка открытия десктопного приложения или формы задачи, а также ошибка сохранения связи не отменяют успешное проведение заказа.
- Если десктопное приложение отсутствует, не запускается, не авторизовано в нужном портале или не может открыть нужную форму, сообщить о препятствии и необходимых действиях в приложении или его настройках. Браузер не открывать, задачу автоматически не создавать, существующую связь сохранять. После устранения причины сотрудник может повторить действие.
- Сообщение должно различать ошибку открытия формы и ошибку сохранения ссылки на уже созданную задачу, предлагая повторить действие или вставить ссылку вручную.
- Задача не должна автоматически создаваться повторно при повторной доставке уведомления или повторной попытке сохранить связь.
- Если задача уже создана, а связь ещё не записана, повторная попытка интеграции должна восстановить связь с этой задачей. При неизвестном результате сначала проверять ту же операцию, показывать «Проверяем, создана ли задача» и временно блокировать повторное создание для этого заказа. Потеря ответа и повторное нажатие «Создать» не должны создавать дубль. Работа с другими заказами остаётся доступной.
- Для отказа от задачи не вводится отдельный флажок: сотрудник закрывает форму; при следующем проведении без связи напоминание повторяется.
- Запись связи в заказ не должна повторно проводить документ, менять его содержимое или вызывать новое открытие Б24.
- При одновременной работе сотрудников проверять существующую связь и уникальность связи один к одному при её сохранении. Проверка и сохранение должны исключать одновременное закрепление одной задачи за разными заказами. Конфликт не должен приводить к молчаливой потере ссылки.
- Одновременное создание двумя сотрудниками не является ожидаемым рабочим сценарием. Атомарная защита связи сохраняется: первая записанная связь не заменяется последующей, конфликт фиксируется в диагностике, задачи автоматически не удаляются. Сложный отдельный интерфейс конфликта не разрабатывать; предполагаемую блокировку формы штатной 1С проверить отдельно, не считать доказанной.
- При удалении связанной задачи или отсутствии доступа к ней сохранять связь и не открывать создание новой задачи автоматически. Результат проверки показывать отдельно; исправление выполняется командами «Изменить связь» и «Удалить связь». Отсутствие доступа не считать удалением задачи.
- При доступных системах и работающем клиенте 1С автоматически сохранять связь не позднее 60 секунд после создания задачи. Если клиент 1С закрыт, восстанавливать связь не позднее 60 секунд после следующего запуска при доступных системах. Механизм должен сохранять сведения, необходимые для такого восстановления.
- Диагностика должна позволять определить заказ, этап операции и причину сбоя, не записывая секреты доступа.

## 8. Требования к реализации и передаче

Доработку стороны 1С выполнить расширением конфигурации без изменения основной конфигурации. Элементы формы заказа и списка, хранение связи и обработчики реализовать в расширении. На этапе технической проверки использовать собственный регистр сведений расширения с атомарной уникальностью связи по разделам 4 и 7; структуру и точки записи подтвердить прототипом и зафиксировать в решении T10.

Разрабатывать и проверять расширение в тестовой копии базы. Сохранить штатную логику проверок, записи, проведения и закрытия формы заказа. Клиентское открытие десктопного приложения Б24 выполнять в сеансе инициировавшего действие сотрудника. Если выполнить требование средствами расширения невозможно, отдельно согласовать решение до основной разработки; изменения основной конфигурации без такого согласования не допускаются.

Поставить программисту:

1. Файл расширения `.cfe` с указанием проверенных версий платформы и конфигурации, а также режимов совместимости.
2. Список собственных и заимствованных объектов расширения, добавленных реквизитов, процедур и точек подключения.
3. Исходники расширения и инструкции по установке и настройке.
4. Компоненты и настройки стороны Б24, если они необходимы для возврата связи.
5. Сценарии проверки и фактические результаты тестирования с перечислением ограничений.

Доступы и адрес информационной базы задавать настройками, а не персональными путями разработчика. Секреты интеграции не включать в передаваемые исходники и `.cfe`. Права пользователя 1С и Б24 должны проверяться штатными механизмами.

После успешной проверки в тестовой копии базы программист устанавливает проверенное расширение в рабочую базу с учётом существующих доработок и расширений. Поставка доработанной конфигурации `.cf`, её замена и перенос изменений через сравнение и объединение не входят в выбранный способ внедрения. Допускаются приложение Б24, промежуточный сервис и настройка рабочих мест. Состав компонентов, размещение, стоимость и необходимые доступы согласовать по результатам технического прототипа до основной разработки.

Настройка Б24, промежуточного сервиса при его использовании и рабочих мест должна быть описана отдельно: одного `.cfe` может быть недостаточно для открытия формы и возврата связи.

## 9. Приёмочные сценарии

| Проверка | Ожидаемый результат |
| --- | --- |
| Успешное «Провести и закрыть», связи нет | На ПК сотрудника без дополнительных действий открывается заполненная форма новой задачи внутри десктопного Б24 |
| Десктопное приложение закрыто | Приложение запускается и открывает нужную форму при наличии действующей авторизации; браузер не открывается |
| Десктопное приложение отсутствует, неисправно или не авторизовано | Показано сообщение с необходимыми действиями; проведение заказа и существующая связь сохраняются; перехода в веб-версию и автоматического создания задачи нет |
| Переход по ссылке из формы заказа или списка | Нужная задача открывается только в десктопном Б24; при невозможности открытия показана ошибка без перехода в браузер |
| Ошибка проведения | Форма Б24 не открывается, задача не создаётся |
| Только «Записать» или «Провести» | Автоматического открытия нет |
| Закрытие формы Б24 без создания | Задача и связь отсутствуют; проведение заказа сохраняется |
| Следующее проведение без связи | Следующее успешное «Провести и закрыть» снова открывает форму новой задачи |
| Создание задачи | Номер и ссылка автоматически записываются в исходный заказ |
| Заполнение новой задачи из 1С | По умолчанию: название `{Контрагент}.`; постановщик — Оксана, исполнитель — Люда, проект — «Гем платежи», наблюдатель — Инга, соисполнитель — Женя; поля доступны для ручных изменений |
| Создание задачи разными сотрудниками | По умолчанию подставляются согласованные участники и проект, включая Оксану постановщиком; техническая подмена текущим сотрудником не допускается; ручные изменения сохраняются |
| Крайний срок новой задачи | При открытии формы — текущий день, 23:59 UTC+5; сотрудник может изменить срок |
| Ручное изменение заполненных полей | Изменения названия, описания, участников, проекта и срока сохраняются; интеграция их не отменяет |
| Заказ изменён после открытия формы задачи | Описание сохраняет данные на момент открытия и ручные правки сотрудника |
| Результат создания неизвестен | Проверяется прежняя операция, повторное создание временно заблокировано; созданная задача не дублируется |
| Ручная кнопка в несохранённом заказе | Сначала штатная запись без проведения; ошибка записи не открывает Б24; крестик не удаляет сохранённый заказ |
| Ссылка в форме заказа и списке | В форме показан полный кликабельный адрес; в колонке «Задача Б24» после «Клиент» — кликабельный текст `Задача №{ID}`; оба представления используют одну связь |
| Отказ от создания задачи при пустой связи | Поле ссылки в заказе и ячейка списка остаются пустыми |
| Привязка существующей задачи | Название, участники, проект и срок существующей задачи не изменяются |
| Повторное проведение со связью | Новая форма задачи не открывается |
| Ручная кнопка в заказе без связи | Открывается заполненная форма задачи, сохранение задачи остаётся ручным |
| Ввод существующей ссылки | Номер и ссылка сохраняются; переход открывает нужную задачу |
| Ошибка возврата ссылки | Заказ проведён, созданная задача не теряется; доступно восстановление связи без дубля |
| Задача уже связана с другим заказом | Ручная и автоматическая привязка к другому заказу запрещены; существующая связь сохраняется |
| Изменение или удаление связи | Требуются право изменения заказа и подтверждение; фиксируются пользователь, время, прежняя и новая связь |
| Удалённая или недоступная задача | Связь сохраняется, новая форма автоматически не открывается; результат проверки показан отдельно |
| Срок возврата связи при работающем клиенте | При доступных системах связь записана не позднее 60 секунд после создания задачи |
| Клиент 1С закрыт до возврата связи | При доступных системах связь восстановлена не позднее 60 секунд после следующего запуска |
| Два сотрудника | Форма Б24 открывается у инициатора; заполнение по умолчанию не зависит от него; запись связи не допускает молчаливой замены |
| Установка расширения в тестовую копию базы | Расширение применяется без изменения основной конфигурации; блок в форме заказа, колонка списка и хранение связи работают |
| Новый сеанс 1С с подключённым расширением без EPF и MCP | Функции интеграции работают |

Проверки проводить в тестовой базе и на тестовых задачах через десктопное приложение Б24. Отдельно зафиксировать проверку на рабочих типах ОС, клиента 1С и версии десктопного Б24. Во всех пользовательских сценариях проверить отсутствие открытия веб-версии. Результат исторического прототипа не заменяет приёмку десктопного сценария, автоматического сохранения связи.

## 10. Технические вопросы до основной разработки

Функциональное поведение и реализация стороны 1С через расширение согласованы. Достаточность возможностей расширения для всех требований пока не подтверждена; следующие механизмы необходимо выбрать и проверить небольшими прототипами:

- Применимость расширения к согласованным версиям платформы и конфигурации с учётом режимов совместимости, существующих доработок и расширений. Проверить добавление элементов формы заказа и списка, хранение связи и обработку успешного «Провести и закрыть» без изменения основной конфигурации.

- Способ открытия заполненной формы Б24 с сохранением возможности закрыть её без создания задачи.
- Возможность сохранить задачу с постановщиком Оксаной при работе другого сотрудника в своей учётной записи, предзаполненными участниками, проектом и сроком на момент открытия формы. Проверить сохранение ручных изменений; запуск приложения без заполненной формы не подтверждает раздел 5.
- Работа только через десктопное приложение Б24: проверить запуск или активацию приложения из 1С, выбор нужного портала, открытие заполненной формы новой задачи и существующей задачи, возврат связи. Проверить приложение в запущенном и закрытом состоянии, а также поведение при отсутствии установки или авторизации. Открытие формы задачи внутри десктопного приложения пока не подтверждено; запуск приложения сам по себе не подтверждает выполнение сценария. Зафиксировать поддерживаемую версию приложения и настройки рабочих мест. Браузерный прототип не заменяет эту проверку.
- Способ получения идентификатора созданной задачи и надёжного сопоставления с исходным заказом, включая закрытую форму заказа и повторную доставку событий.
- Доступность необходимых интеграционных возможностей на текущем портале, права администратора и способ авторизации.
- Поддерживаемые ОС рабочих мест, версия рабочей конфигурации и отличия от тестовой базы.

Основную разработку начинать после подтверждения небольшими прототипами обоих механизмов с использованием расширения на согласованных версиях платформы и конфигурации в тестовой копии базы:

1. Открытие из 1С заполненной формы внутри десктопного Б24 с ручным сохранением задачи, предзаполнением по разделу 5 и сохранением ручных изменений и возможностью закрыть форму без создания.
2. Автоматический возврат связи в заказ с закрытой формой, включая восстановление после закрытия клиента 1С и соблюдение сроков раздела 7.

Сначала проверять стандартную форму Б24. При её недостаточности записать конкретное ограничение; собственную форму внутри десктопного клиента внедрять только после отдельного согласования пользовательского сценария.

Для прототипа хранения использовать собственный регистр расширения с атомарным контролем связи. Кандидат обмена — постоянно доступный сервис с устойчивым хранением операций; файловая база в сетевой папке сама по себе не является работающим обработчиком. Минимальный контракт: идентификаторы базы, заказа и операции, состояние попытки, ID созданной задачи, подтверждение записи связи. Не сопоставлять по названию или сумме. Размещение, авторизацию и способ получения результата определить по фактическим проверкам.

Все текущие прототипы выполнять в существующей «КА Демо» и проекте «Гем платежи демо», без добавления участников в демопроект и изменения рабочих объектов. Права назначения реальных участников и сценарий другого сотрудника остаются отдельным условием завершения. Совместимость с рабочей базой проверить перед внедрением. Результаты этапа 1 вести в `docs/stage-1-prototypes.md`.

Для каждого механизма зафиксировать фактический результат, ограничения и необходимые компоненты. Выбранное решение, состав компонентов, размещение, стоимость и необходимые доступы согласовать до основной разработки. Неподтверждённый механизм остаётся открытым условием и не считается выполненным требованием. Нельзя подменять согласованное ручное создание задачи её автоматическим сохранением ради упрощения интеграции. Если механизм не позволяет выполнить требование, согласовать изменение объёма с заказчиком.

## 11. За пределами первой версии

- Веб-версия Б24: полностью исключена из пользовательских сценариев интеграции, включая запасной переход при ошибках десктопного приложения.
- Формирование Word-документа по данным 1С и автоматическое прикрепление его к задаче Б24. Отложено заказчиком; тип документа, шаблон, момент загрузки и правила обновления вложения пока не согласованы. В первой версии файлы из 1С автоматически в Б24 не передаются.
- Счета на оплату внутри Б24. Рассмотреть отдельно для полноценной версии; это возможное направление, а не согласованное обязательство. Учесть исходную позицию директора о ведении счетов в КА.
- Автоматическое сохранение задачи без решения сотрудника.
- Несколько связанных задач в одном заказе.
- Создание и открытие новых заказов из Б24, включая действие «Создать в КА».
- Автоматический подбор клиента и заполнение строк заказа из Б24.
- Синхронизация статусов, сроков, платежей и содержимого заказа с задачей.

## 12. Основания и приоритет требований

Основания: исходное описание задачи Б24 №9866, предоставленная переписка, подтверждённый прототип и ответы заказчика в текущем согласовании.

При расхождении исходного описания и согласованных ответов применять решения этого ТЗ: документ «Заказ клиента»; реализация стороны 1С расширением без изменения основной конфигурации, поставка `.cfe` и установка после проверки в тестовой копии базы; работа через десктопное приложение Б24; автоматическое открытие плюс отдельная кнопка; сохранение задачи только пользователем; связь заказа и задачи строго один к одному; обратное создание заказа из Б24 исключено; название новой задачи — `{Контрагент}.`; значения предзаполнения по разделу 5 с возможностью ручного изменения; крайний срок по умолчанию — день открытия формы, 23:59 UTC+5; ссылка отображается в форме заказа и списке «Заказы клиентов». Новые технические детали, явно отмеченные как требующие проверки, не считать уже реализованными.
